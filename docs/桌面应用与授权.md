# 桌面应用与授权

## 技术选型：PySide6 + PyInstaller

引擎全是 Python（pandas / openpyxl，后面还要上 OR-Tools）。走 Electron 或 Tauri
就得再养一套 Node/Rust 工具链，外加把 Python 打成 sidecar 跟着壳一起发，CI 复杂度翻倍；
而这个应用的核心界面是**课表网格**，Qt 的表格控件正好是强项。所以两端都用
PySide6 写，PyInstaller 打包，一套语言、一条 CI 矩阵。

> PySide6 是 LGPLv3。PyInstaller 是动态链接方式打包，商业分发没问题；
> 如果将来要做静态链接或改 Qt 源码，需要另外确认许可条款。

## 两个端

| | 用户端 `EduShift` | 管理端 `EduShiftAdmin` |
|---|---|---|
| 给谁 | 排课员 | 管理员本人 |
| 密钥 | **只有公钥**（构建时编译进去） | **持有私钥**（口令加密存在本机） |
| 能干什么 | 导入排班明细 → 体检 → 看违规清单 → 导出；后续加自动排班和看板 | 生成密钥对、签发许可、查台账 |
| 打包体积 | 含 pandas，约 240 MB | 排除了 pandas/numpy，约 150 MB |
| 分发 | 随产品发给所有用户 | **只发给管理员，不要随产品分发** |

管理端产物里**没有任何密钥**。密钥是管理员在自己机器上生成、自己保管的。

## 授权是怎么工作的

管理端「密钥」页只有四个按钮，不用管文件路径：

| 按钮 | 干什么 |
|---|---|
| 生成私钥 | 第一次用点这个。设口令 → 程序自己找地方存好 |
| 导入私钥 | 已经在别的机器上生成过，选那个 .pem 导进来（口令不变） |
| 解锁 | 每次重开程序，输一次口令把私钥载入内存 |
| 备份私钥 | 另存一份加密的 .pem 到离线的地方。**生成后立刻做** |

```
管理端                                     用户端
──────                                     ──────
「生成私钥」→ 口令加密存在本机
            ← 程序自己保管，用户不用碰路径
公钥那一串   ─────────────────────────────→ 钉进 licensing/gate.py

填表签发 xxx.lic
  {payload: {客户, 到期, 席位, 设备指纹, 功能档位}, sig: 私钥签名}
                     ──── 发给用户 ────────→ 点「导入许可」
                                              用公钥验签
                                              查到期 / 查设备 / 查功能档位
```

签名对象是 payload 的规范化 JSON（键排序、无空格、UTF-8）。任何字段被改一个字符，
验签立刻失败——所以用户没法自己把有效期从 2026 改成 2099。

### 校验项

| 项 | 说明 |
|---|---|
| 签名 | 必须由管理端私钥签发，别人的私钥签的不认 |
| 有效期 | 到期即停。容忍 ±24 小时时钟偏差 |
| 签发时间 | 系统时间早于签发日会被拒（防把时钟调回去） |
| 设备绑定 | 机器指纹白名单；留空 = 不绑定，任意机器可用 |
| 功能档位 | `health_check` / `solver` / `board` / `export`，可以只卖其中几项 |

机器指纹取各系统自带的机器 ID（Linux `/etc/machine-id`、macOS `IOPlatformUUID`、
Windows `MachineGuid`），加盐哈希后取 16 位。不含个人信息，也不回传任何东西。

### 说清楚边界

**公钥放客户端，防的是「伪造授权」，不是「破解」。** 用户没有私钥，签不出一张有效许可；
但有人反编译客户端、把验签那一行 `if` 改掉，这套机制拦不住。这是所有离线授权的天花板。

它的定位是**管理正常用户的使用**——到期、席位、功能档位——不是对抗逆向。
真要提高破解成本，得上联网激活 + 服务端校验，那是另一个量级的工程。

**离线也做不到真正的吊销。** 已经发出去的许可在到期前一直有效。能做的是：
签短期许可（比如 90 天）滚动续期，把「续不续」变成实际的控制手段。

## 构建与发布

`.github/workflows/build.yml`：

```
test（ubuntu）── 全量 pytest，不过就不往下走
      ↓
build（矩阵）── macos-14 (arm64) / macos-15-intel / windows-latest (x64)
      ├─ 在目标平台再跑一遍 pytest
      ├─ 写入公钥（来自 Secret LICENSE_PUBLIC_KEY_B64）
      ├─ PyInstaller 打两个端
      ├─ 跑产物自检 --selftest（验依赖全冻进去了、公钥嵌进去了、引擎能算）
      └─ 上传 6 个产物
      ↓
release（仅 v* 标签）── 挂到 GitHub Release
```

### 公钥怎么进用户端

优先级：**Secret > 源码里钉死的值 > 占位符**。

1. **钉进源码**（默认做法）。管理端「密钥」页复制那串公钥，写进
   `licensing/gate.py` 的 `PUBLIC_KEY_B64`，提交。公钥本来就是公开的，进仓库没问题，
   而且这样构建是可复现的——谁 clone 下来打包，出来的都是同一把公钥。
   用 `python tools/embed_pubkey.py --verify` 可以确认当前钉的是什么。
2. **仓库 Secret `LICENSE_PUBLIC_KEY_B64`**（可选）。配了就覆盖源码里的值，
   用于轮换密钥而不想改代码的场合。
3. 两个都没有 → 保留占位符，产出的用户端自检会明确报「未嵌入公钥」，跑起来也用不了。
   这是故意的，免得把一个验不了签的包发出去。

**私钥永远不要放进 Secret，也不要进仓库。** 验签只需要公钥。

### 代码签名

目前产物**未签名**：

- macOS：首次打开要右键 →「打开」，或 `xattr -dr com.apple.quarantine EduShift.app`
- Windows：会有 SmartScreen 提示

要去掉这些提示，需要 Apple Developer ID（$99/年）和 Windows 代码签名证书。
证书拿到后，在 workflow 里加签名和公证步骤即可，现在的结构不用改。
