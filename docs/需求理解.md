# 排班小工具 · 需求理解（v0.1）

> 依据：`20240716154132910_54.xlsx`（661 行 × 45 列 的排班明细）+ 透视截图 + 本次对话中口述的规则。
> 文中所有统计数字都由 `analysis/explore_source.py` 跑原始表得出，可复算。

---

## 0. 一句话概括

现在的流程是「人在 Excel 里手工把 200 多个团队拖进时段格子里」；
要做的工具是把它反过来——**输入维度关键词 + 人员池 + 规则，自动吐出这张排班表**，并且顺带产出截图那种看板视图和一份冲突报告。

```
输入：待排团队清单 + 可用指导员 + 场地 + 规则参数
  ↓  求解
输出：① 排班明细表（与现有导出同结构）
      ② 中心 × 段次-时段 看板（截图那张）
      ③ 指导员个人课表 + 工作量统计（Sheet1 那张）
      ④ 冲突/未排上 报告
```

## 1. 素材读到了什么

### 1.1 三份东西其实是一件事

| 素材 | 是什么 | 结论 |
|---|---|---|
| `20240716154132910_54` 明细表（661 行） | 排完之后的结果，一行 = 一个团队（一个班） | **唯一事实源** |
| 截图那张网格 | 明细表的透视：行 = 区域/校区，列 = 段次 × 时间段 | 派生视图 |
| `Sheet1` 透视 | 主指导员 × 段次 的课量统计 | 派生视图 |

所以工具**只要把明细表排出来**，看板和工作量统计都能自动生成，不需要单独维护。

截图单元格的格式是：`S7/LI/英/梁峰玮/22` = `程度 / 团队类型 / 产品简称 / 主指导员 / 人数`。

### 1.2 维度骨架（来自原表的真实取值）

| 维度 | 取值数 | 实际值 | 在工具里的角色 |
|---|---|---|---|
| 区域 | 4 | 宝安南山区、福田区、龙华区、罗湖龙岗区 | 输入（决定"就近"） |
| 中心 | 30 | 百花科学、百花文学、石厦科学… | 输入 |
| **校区** | **20** | 百花、石厦、翠竹…（去掉"科学/文学"后缀） | **派生，冲突判定的关键粒度** |
| 段次 | 4 + 不分段 | 段次1–4 | 输入（分开求解） |
| 周 | 5 | 星期二/三/五/六/日 | 输入或决策变量（待确认） |
| 时间段 | 6 | 08:10-10:10、10:30-12:30、(13:30-15:30)、14:00-16:00、16:20-18:20、18:30-20:30 | **决策变量** |
| 程度 | 3 | S7 / S8 / S9 | 输入 |
| 产品 | 5 | 编程理论、双语文化、文学美育、躬行实践、溯源 | 输入 |
| 团队类型（层级） | 5 | LI 励学、LE 乐学、BO 博学、CX 创新、ZY 卓越 | 输入 |
| 主指导员 | 106 | — | **决策变量** |
| 指导室 | 1–11 间/中心 | 01–15 号教室 | 决策变量（可选） |
| 是否促销 | 2 | 是 / 否 | 输入（截图里"促销班/常规班"两块） |

### 1.3 五个容易踩坑的点（都从数据里验证过）

1. **中心 ≠ 校区。** 30 个中心其实是 20 个校区：`百花科学` + `百花文学` 是同一个校区的两栋楼。截图第二列写的"百花"是**校区**。冲突判定必须按校区，不是按中心 —— 学生不会因为你换了栋楼就能分身。
2. **文学中心只上文学美育**（26/26 行），科学中心和综合中心什么都上。所以"产品 → 可用中心"本身就是一条硬约束。
3. **指导员基本是"单产品"的**：106 人里 103 人只教 1 个产品，唯一的跨产品组合是「溯源 + 躬行实践」（3 人）。**产品资质是选人时的硬门槛**，不是偏好。
4. **看板里的人数字段导出表里没有**，可以反算：`购买服务时长分钟数 ÷ (团队分钟数 × 本团队服务次数)`，84% 能整除，均值 15.9（容量 24），除 1 行外都 ≤ 服务容量。基本可以确认是**在读人数**（非整数应该是中途插班导致的）。
5. **段次 ≈ 期段**，且基本绑定星期几：段次1→星期六（200/216），段次2→星期三/星期五，段次3、段次4→星期五。规模上每个段次是 106–216 个团队、18–26 个中心、55–95 位老师、4–6 个时段。

## 2. 工具要做什么

### 2.1 输入（你说的"输入这些关键词"）

**① 待排团队清单（需求侧）** —— 要排哪些课
```
段次 | 中心 | 程度 | 产品 | 团队类型 | 平行班数量 | 是否促销 | 本团队服务次数
```
（如果直接拿现有明细表当输入，把"周 / 时间段 / 主指导员"三列清空即可）

**② 人员池** —— 你说的"我就这些人，让他去排"
```
主指导员 | 可教产品 | 可去的中心（或区域） | 不可用的星期/时段 | 单日最多几节
```

**③ 场地**
```
中心 | 教室数 | 各教室座位数
```

**④ 规则参数** —— 这是工具的灵魂，做成配置文件（yaml）而不是写死在代码里
```
必须相邻的产品组：[编程理论, 双语文化]
中心邻近表：哪些中心算"挨得近"（见 §5 Q3）
单人单日上限：最多 N 节、最多跨 M 个中心、转场至少留 K 分钟
各约束的权重
```

### 2.2 决策变量

对**每一个团队**决定：`(星期几, 时间段, 主指导员, 指导室)`

### 2.3 输出

1. **排班明细表** —— 和现有导出同结构，能直接回灌/做 diff 对比
2. **看板透视** —— 截图那张，行 = 区域/校区，列 = 段次 × 时段，格子里 `程度/类型/产品/老师/人数`
3. **指导员课表** —— 每人一天的行程（几点在哪个中心上什么），以及 Sheet1 那种课量统计
4. **冲突 & 未排报告** —— 哪些团队没排上、为什么（缺老师？缺教室？时段冲突？），哪些软约束被牺牲了

## 3. 约束清单

### 3.1 硬约束（违反 = 这个排班不能用）

| # | 约束 | 说明 | 现有数据的执行情况 |
|---|---|---|---|
| H1 | 一个指导员同一时段只能在一个团队 | 老师不能分身 | ✅ 0 违反（661 行里没有一例） |
| H2 | **同时段 + 同校区 + 同程度 + 不同产品 不能同时排课** | 你明确提的第 1 条规则。等价于：一个校区一个时段里，同一年级的所有班必须是**同一个产品**（可以有多个层级/多个平行班） | ❌ 409 组里 164 组违反（**40%**） |
| H3 | 同一时段同一中心，并发团队数 ≤ 教室数 | 场地上限 | ✅ 0 违反（有教室数据的 217 行） |
| H4 | 只能把老师排到他能教的产品上 | 103/106 只教 1 个产品 | ✅ 按定义成立 |
| H5 | 老师/中心/时段的可用性黑名单 | 请假、只在某几个中心 | 需要新增输入 |

> **H2 是这个工具最大的价值点。** 现有手工排班在 40% 的「校区 × 年级 × 时段」组合里放了两个以上不同产品，涉及 407 个团队。举个真实的例子——百花校区 段次1 S7 层级 LI：
> ```
> 10:30-12:30  编程理论 LI1（郑政）  ← 同一时段
> 10:30-12:30  双语文化 LI1（曾彤）  ← 两个不同产品
> 14:00-16:00  编程理论 LI2（郑政）  ← 同一时段
> 14:00-16:00  双语文化 LI2（曾彤）  ← 又撞一次
> ```
> 一个 S7 同时报了这两门的学生，只能"编程 10:30 + 双语 14:00"这一种走法，稍微多一个班就完全排不开。

### 3.2 软约束（尽量满足，可加权取舍）

| # | 约束 | 你的原话 | 现状基线 |
|---|---|---|---|
| S1 | **捆绑产品必须相邻** —— 同校区同程度（同层级）的两个指定产品必须占**连续时段**（8:10-10:10 接 10:30-12:30） | "编程理论跟双语文化一定要挨着" | 看口径：中间不夹别的课 **60%**；要求等待 ≤30 分钟则只有 **38%**（差的 22 个百分点全是跨午休的 10:30→14:00） |
| S2 | **老师当天尽量固定在一个中心** | "尽可能安排在同一个中心" | 72% 的老师当天只在 1 个中心，83 人次跨 2 个中心，5 人次跨 3 个 |
| S3 | **必须跨中心时，越近越好** —— 优先级：同校区（百花科学→百花文学）> 同区域 > 邻近区域；并且要留够转场时间 | "跨到宝安中心区旗舰科学…尽可能挨得近一点" | 96 次跨中心转场中，**24 次是背靠背的相邻时段**；27 人次要跨区域 |
| S4 | 老师当天课程尽量连续，少空档 | — | 227 个多节课人次里 170 个有空档，平均空 1 个时段 |
| S5 | 工作量均衡 | — | 人均 6.2 个团队，最多 13 个 |
| S6 | 促销班优先占黄金时段？ | 截图分了"促销班/常规班"两块 | 待确认（见 Q8） |

> **时段之间的空隙极不均匀**，这直接决定了"挨着"和"赶得及"两件事：
> ```
> 08:10-10:10 → 10:30-12:30   空 20 分钟
> 10:30-12:30 → 14:00-16:00   空 90 分钟   ← 唯一能跨中心跑场的窗口
> 14:00-16:00 → 16:20-18:20   空 20 分钟
> 16:20-18:20 → 18:30-20:30   空 10 分钟
> ```
> 换句话说，**除了午休那一档，老师换中心根本来不及**。现有排班里有 24 次转场只有 10–20 分钟，
> 其中 卢俊杰 要在 10 分钟内从翠竹科学（罗湖）赶到东海城市广场科学（福田），
> 李林辉 要在 20 分钟内从翠竹科学赶到百花科学。这几条在地图上就是不可能完成的。

> **S1 和 H2 是一对。** H2 把同年级的不同产品**推开到不同时段**，S1 又要求指定的几个产品**紧挨着**。合起来的效果就是：一个校区的 S7，理想排法是 `8:10 编程 → 10:30 双语 → 14:00 文学` 这样一条连续的链。这也解释了为什么"挨着"是最麻烦的点——它是全局耦合的，改一个格子会牵动整条链。

## 4. 目标函数

硬约束进模型当约束，软约束进目标函数当惩罚项，权重可配：

```
minimize  w1 × 未排上的团队数            （最优先，通常给极大权重）
        + w2 × 捆绑产品不相邻的对数        （S1）
        + w3 × 老师当日跨中心次数          （S2）
        + w4 × 转场距离分（同校区0 / 同区域1 / 跨区域3）  （S3）
        + w5 × 老师课表空档段数            （S4）
        + w6 × 工作量方差                  （S5）
```

有了这个打分，还能顺手做一件事：**给现在这版手工排班打分**，然后对比工具排出来的分，直接量化"好了多少"。

## 5. 问题与结论

| # | 问题 | 结论 | 落地方式 |
|---|---|---|---|
| Q1 | 规则 1 的粒度 | ✅ **做成配置**。程度 = 年级，当前项目取值 S7/S8/S9，一个学生只属于一个程度、跨产品不变，所以它能当"同一撮学生"的判定字段 | `冲突口径.分组字段`，默认 `[校区, 程度]`；往列表里加 `团队类型`、`班序` 即逐级放宽 |
| Q2 | 哪些产品必须挨着 | ✅ **后台配置**。每条规则单独设强度（硬/软）、顺序、最大等待分钟数 | `连堂.规则[]`，已预置「编程理论+双语文化（硬）」和「双语文化+文学美育（软）」 |
| Q3 | "近"怎么算 | ✅ **地理位置的近**，接高德 API 算 | 两个工具各跑一次：`geocode_centers.py` 地址→经纬度，`travel_matrix.py` 两两驾车时间/里程。之后排班完全离线。判定口径 `地理.判定方式` 可选**时间**或**距离** |

剩下五个仍按默认值跑，随时可改：

| # | 问题 | 为什么要问 | 默认假设 |
|---|---|---|---|
| Q4 | **星期几是工具来定，还是按段次固定**？ | 数据里段次1 基本=星期六、段次3/4=星期五，看起来是固定的 | 默认按段次固定（作为输入），可选开放成决策变量 |
| Q5 | 看板里的**人数**取哪个字段？导出表里没有这一列 | 我反算出来是"在读人数"，但想确认口径（报名数？实到数？） | 用 `购买时长 ÷ (团队分钟 × 服务次数)` |
| Q6 | 一个老师**一天最多几节、最多跨几个中心、转场至少留多少分钟**？ | 硬上限和软惩罚要有个数 | 默认：≤4 节、≤2 个中心、跨中心至少隔 1 个完整时段 |
| Q7 | 是**从零重排**，还是在现有排班上做**最小改动的修复**？ | 两种模式的算法和交付形态不一样。学期中途通常只能修，不能推翻 | 两个模式都做：`--mode rebuild` / `--mode repair`（repair 会额外惩罚"和原排班不同"的格子） |
| Q8 | **促销班和常规班**是一起排还是分开排？截图看着是分成两块的 | 影响是否要拆成两个子问题 | 一起排（同一批老师和教室），只在看板上分开展示 |

## 6. 配置长什么样

三个决策都落在 `config/rules.example.yaml` 里，改规则不动代码：

```yaml
冲突口径:
  分组字段: [校区, 程度]          # Q1 · 加 团队类型 / 班序 即逐级放宽

连堂:                             # Q2 · 后台配哪些课要挨着
  分组范围: [校区, 程度, 团队类型]
  规则:
    - 名称: 编程双语连堂
      产品: [编程理论, 双语文化]
      强度: 硬
      最大间隙_分钟: 30           # 填 30 排除跨午休；填 120 则午休也算挨着

地理:                             # Q3 · 按地图算
  中心坐标表: config/centers.csv
  通行时间表: config/travel.csv    # 地图 API 跑出来的真实驾车时间/里程
  判定方式: 时间                   # 时间 | 距离，二选一
  时间: {安全余量_分钟: 10}        # 赶路时间 ≥ 通行时间 + 余量
  距离: {上限_km: 8}               # 改成「距离」时用这个
  估算: {直线折算系数: 1.4, 平均车速_kmh: 22, 固定开销_分钟: 15}
  违规级别: 软                     # 软 = 扣分；硬 = 判不可行
```

数据来源按可信度排队，前面有就不用后面的：

| 顺序 | 来源 | 怎么来的 |
|---|---|---|
| ① | `config/travel.csv` | 真实驾车时间/里程，`tools/travel_matrix.py` 跑一次 |
| ② | 经纬度直线估算 | 直线 km × 折算系数 ÷ 车速 + 固定开销 |
| ③ | 同校区 / 同区域 / 跨区域 | 连坐标都没有时的兜底，体检报告里会明确标出来 |

准备数据（各跑一次，之后排班完全离线、不需要网络也不需要 key）：

```bash
python tools/geocode_centers.py --key <高德Key>    # 地址 → 经纬度，就地写回 centers.csv
python tools/travel_matrix.py   --key <高德Key>    # 两两驾车时间/里程 → travel.csv
```

30 个中心 = 30 次调用，在高德免费额度内。

## 7. 技术方案建议

**规模**：按段次拆分后，最大的子问题是段次1 —— 216 个团队 × 5 个时段 × 95 位老师。这个量级对约束求解器来说很轻松（秒级）。

```
读入 xlsx ──► 规范化(pandas) ──► 建模 ──► 求解 ──► 写出 xlsx / 看板
                                  │
                       OR-Tools CP-SAT
                       变量: x[团队, 时段], y[团队, 老师], z[团队, 教室]
                       兜底: 贪心初始解 + 局部搜索(2-opt 换时段/换人)
```

- **数据层**：`pandas + openpyxl`，把明细表规范化成内部模型（团队 / 中心 / 校区 / 老师 / 时段）
- **求解层**：`OR-Tools CP-SAT`。硬约束直接建模，软约束进目标函数加权求和。求不出可行解时，自动放松软约束并报告"为了排下去牺牲了什么"
- **输出层**：写回 xlsx（明细 + 看板两个 sheet，看板带颜色分块），另出一份冲突报告
- **交付形态**：先做 CLI（`python schedule.py --input 团队清单.xlsx --config 规则.yaml --out 排班表.xlsx`），跑通之后再考虑套一个网页界面

**关于原始数据**：那份 xlsx 里有 106 位真实指导员姓名和门店信息，**不建议提交进仓库**。开发用脱敏样例数据，字段结构见 §1.2。
