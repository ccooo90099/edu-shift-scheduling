---

## 一、这是什么

深圳一家**教培**机构（不是托管）的分校排课。学生按报名科目来上课，课间不留校，午休家长接走。

现在是人在 Excel 里把两百多个班手工拖进「中心 × 时段」的格子。要做的是反过来：**给定要开的课、可用的老师、规则，自动排出这张表**。

## 二、名词

### 产品就是科目 〔定〕

| 产品 | 科目 | 从哪个年级开始 |
|---|---|---|
| 编程理论 | 数学 | S7 |
| 双语文化 | 英语 | S7 |
| 文学美育 | 语文 | S7 |
| 躬行实践 | 物理 | S8 |
| 溯源 | 化学 | S9 |

初一语数英，初二加物理，初三加化学。

### 程度 = 年级 〔定〕

S7 / S8 / S9 = 初一 / 初二 / 初三。一个学生只属于一个程度，跨科目不变。

### 团队类型 = 能力分层 〔定〕

LI 励学 · LE 乐学 · BO 博学 · CX 创新 · ZY 卓越。

排在一起的课**层级必须一致**——不能让励学班和乐学班的学生混着连堂。

### 中心 ≠ 校区

30 个中心落在 20 个校区上：「百花科学」和「百花文学」是同一校区的两栋楼。

- **校区**是学生感知的地点 → 学生相关的判定按校区
- **中心**是场地单位 → 教室归中心

文学中心只上文学美育；科学中心和综合中心什么都上。

### 团队 = 一个班

一行 = 一个班 = `(中心, 程度, 产品, 团队类型, 班序)`，人数约 16，容量 24。
排班就是给每个团队定 `(期位, 时段, 主指导员, 指导室)`。

### 人群与报读组合

`(校区, 程度, 团队类型)` 是**同类人群**，不是"同一批人"——里面的学生报的科目并不一样。

**判定单位是「报读组合」**，不是人群，也不是单个团队：

```
人群 = (校区, 程度, 团队类型)
  └─ 报读组合[]  例：{数学+语文: 约22人}、{数学+物理: 约18人}、{只数学: 约6人}
```

连堂、拆天、挪期位，都按**报读组合**判，代价按该组合的人数加权。
**不能拿"年级该上几门"当每个人的科目集合**——只报数学的学生不该被要求把五门课排连贯。

年级只决定**能开哪些科**（S7 没有物理化学），不决定谁报了几科。

### 期位 —— 两个场景共用的同一个维度 〔定〕

| | 寒暑假 | 春秋季 |
|---|---|---|
| **期位 A** | 第一期 | 周六 |
| **期位 B** | 第二期 | 周日 |

暑假的第一期平移到春秋季的周六，第二期平移到周日。所以**不需要「期」和「星期」两个维度，只要一个期位变量**。

期位跟着学生走，有跨季延续性；但**学生中途可以换**（时间不合适就换到另一天的班）。

## 三、时间结构 〔定〕

### 寒暑假

一个批次连上 7–8 天，中间不休；拉到 15 天的话中间休一次。**不分星期几**，每天都是上课日，全天开课。

### 春秋季

周六、周日为主，偶尔有周五晚上。老师周一二休息，周三到周五教研。

### 时段表

| 时段 | 寒暑假 | 春秋季 周六日 | 春秋季 周五 |
|---|---|---|---|
| 08:10-10:10 | ✅ | ✅ | ✗ |
| 10:30-12:30 | ✅ | ✅ | ✗ |
| 14:00-16:00 | ✅ | ✅ | ✗ |
| 16:20-18:20 | ✅ | ✅ | ✗ |
| 18:30-20:30 | ✅ | ✅ | ✅ 仅此一档 |

间隙：`20 分 / 90 分（午休）/ 20 分 / 10 分`。20 分钟以内算课间，50 分钟以上算休息。

## 四、排课规则

### 必须满足

| | 规则 |
|---|---|
| 1 | 一个老师同一时段只能带一个班 |
| 2 | 同时段同中心的并发班数 ≤ 教室数 |
| 3 | 只能把老师排到他能教的科目上（106 人里 103 人只教一科） |
| 4 | 年级决定能开哪些科（S7 没有物理化学） |
| 5 | 后台关掉开关时，**促销班不得排进黄金时段**。黄金时段 = `08:10-10:10`、`10:30-12:30`，只看一天中的时间，两个场景通用。这是硬排除，不是扣分——但要和当天开门的时段取交集（春秋季周五本来就只有晚上一档） |

### 尽量满足

**① 一撮学生的课要连着上** 〔定〕

从好到差三档：

1. **同半天连排** —— 8:10→10:30，或 14:00→16:20→18:30
2. **跨午休连排** —— 10:30→14:00，可接受
3. **分散** —— 中间隔着别的时段，次优但能排上就行

只看**当天**，不跨日。

**② 哪两科优先连堂，看实际报读人数** 〔定〕

常见搭配是数学+语文、数学+英语、语文+英语，**但也有很多数学+物理**。

实际做法是两阶段：先按默认顺序排一版，再看哪个组合的学生多，把人多的组合调到连续时段。
所以配对权重应该是**输入的数据**，不是写死的顺序。

**③ 同时段开多个不同科目是允许的** 〔定〕

```
08:10-10:10  数学
10:30-12:30  语文  ┐ 同一时段两科 —— 可以
10:30-12:30  物理  ┘
```

因为教室和时段根本不够把所有科目平铺开，而且不是所有学生都读全科——只读数学+物理的学生不受影响。还有一部分家长时间凑不齐，主动只报一科。

真正要避免的是：**同一个学生实际报读的那几科撞时段**。扣分多少取决于**同时报这两科的人有多少**。

**④ 老师别到处跑** 〔定〕

- 当天尽量固定在一个中心
- 必须跨中心时越近越好，同校区 > 同区域 > 跨区域
- 路上时间要够：`可用间隔 ≥ 通行时间 + 安全余量`

反面教材（用户原话）：「8 点在宝安带，10 点又到南山去，下午两点又跑到宝安，4 点又跑到南山，太折腾。」

**⑤ 其他**

- 老师当天课表少留空档
- 工作量别太不均
- 周六比周日好排，优先排周六
- 同校区同程度**周六周日都要有班**——新生按程度进班后要挑时间，老生也要能换班，两天都有才有得选
- **教室尽量固定**——同一个班的多次课、同一个老师，尽量待在同一间教室。对老师和学生都更友好。不强求，次优选
- **教室固定不是"同一个班每次都在同一间"**——那个天然成立（一个班只排一次）。要惩罚的是
  **同一位老师在同一中心的不同班之间换教室**

## 五、排不下怎么办 〔定〕

一撮学生要上 3–5 门课，但一个校区一天能给他们开的节数有限（「这个校区周六可能只有两节」）。塞不下就往下退：

| 档 | 安排 | 寒暑假说法 | 春秋季说法 |
|---|---|---|---|
| ① | 全部科目在**本期位**内，同半天连堂 | 都在第一期 | 都在周六 |
| ② | 都在本期位内，但分散了 | 同期不同天 | 同天有空档 |
| ③ | **挪一部分到另一个期位** | 推到第二期 | 周六 2 节 + 周日 1 节 |
| ④ | 彻底排不上 | | |

**「挪到另一个期位」不是失败**，是正常的次优解。目标函数里它的惩罚要明显低于「排不上」。

拆的时候，把人数最多的组合留在同一天连堂，剩下的拆出去。

暑假常规分两期，**每期都尽量覆盖所有年级、所有科目**，覆盖不了的才放第二期。

## 六、输入 / 输出

### 输入

1. **待排团队清单** —— 期位、中心、程度、产品、团队类型、平行班数、是否促销、课次数
2. **各科目组合的学生人数** —— 校区、程度、层级、科目组合、人数
   〔定〕**这是个滚动的估计值，不是精确输入。** 每个季度、每周的报名人数都在变，还有请假。
   **按已报名的人数排满**，不预留空位。后来报名的学生填空缺——进还有余位的班，或者加开新班。
3. **老师配置** —— 姓名、可教科目、可去的中心、不可用时段、单日上限、是否不可调整
   〔定〕后台配置，支持批量改和单个改。排班时按这些属性算可行性。
4. **场地** —— 中心、教室数、座位数
5. **学年日历** —— 各批次的起止日期 〔定〕
   批次就是寒假 / 暑假 / 春季 / 秋季。具体日期每年跟着学校放假时间走，**做成可配置**。
   有了日历才能展开成真实日期，查出跨批次的老师撞车。
6. **中心坐标** —— 地图自动反查；查不到的手动补（见下）
7. **规则参数** —— 场景、时段表、连堂规则、地理判定方式、单人单日上限、各项权重

### 输出

1. **排班明细表** —— 结构和现有导出一致，能回灌做对比
2. **看板** —— 行是区域/校区，列是期位 × 时段，格子里 `程度/层级/科目/老师/人数`
3. **老师课表 + 工作量统计**
4. **问题清单** —— 谁没排上、为什么，牺牲了哪些软规则

### 两种模式

- **重排** —— 从零排
- **修补** —— 学期中途只能改不能推翻，额外惩罚「和原来不同」

## 七、状态清单

我上一轮说"全部结案"，**说过头了**。定了怎么采集不等于数据已经有了，定了做成配置不等于功能已经实现。分开看：

### 规则已定 ✅

上面第二到第六节写的全部内容。这部分可以不管了。

### 方案已定，数据还没有 ⬜

| 数据 | 现状 |
|---|---|
| 中心经纬度 | **一个都没填**，跨中心时间仍是三档粗判 |
| 老师可用性/资质/不可调整 | 无数据，这条约束**还没生效** |
| 学年日历 | 无数据，跨批次的老师撞车**仍查不出来** |
| 各班当前人数与额定容量 | 无数据，新生匹配班级要用 |
| 哪些安排已锁定 | 无数据，局部重排的可改范围要用 |

不阻塞开工，但**阻塞验收**——数据没填之前，"转场时间合理""没有冲突"这类结论都不成立。

### 还是不知道 ⚠️

| | 影响 |
|---|---|
| 看板"人数"到底是什么口径 | 人数是所有加权惩罚的分母，口径错了全都偏 |
| 原表段次1–4 对应几个期位 | 决定 661 行历史数据能不能映射进新模型。映射不了就没有基线，"比手排好多少"无从谈起 |
| 各报读组合的人数 | 连堂优先级和并发扣分都靠它。缺了只能用历史班量做弱代理，且要在报告里标注 |

**这三条不能靠"做成可配置"解决**——可配置提供的是入口，不是信息本身。

## 七之二、坐标怎么来

1. **自动反查** —— 按由细到粗试几种问法：详细地址 → 城市+中心名 → 城市+区域+校区名 → 城市+校区名。命中就停，落在深圳范围外的丢弃。
2. **手动补录** —— 反查不到的，页面上给一个入口：点开跳到地图，用户在地图上找到位置、复制经纬度、粘回来。
3. **顶部告警** —— 只要还有中心没坐标，网页顶部挂一条常驻提示条。**初始化的时候就该引导用户做完这件事。**

没坐标的后果：跨中心的路上时间只能按同校区/同区域/跨区域三档粗判，"赶不赶得及"基本失效。

## 八、数据安全

- 原始表里有 106 位真实老师姓名和门店信息，**不进仓库**
- 真实规则、坐标表、逐人排班、密钥都留本地
- 对外的文档和协作消息只放去标识的汇总
