# 部署到 Hugging Face Spaces

给 demo 用的公网实例。**免费、不要信用卡。**

> 内网生产部署见 [`部署.md`](部署.md)。两者是不同场景，别混。

## 为什么选它

| 平台 | 免费 | 要卡 | 内存 | 数据留得住 |
|---|---|---|---|---|
| **HF Spaces** | ✅ | ❌ | 16GB | ✗ 重启清空 |
| Render 免费档 | ✅ | ❌ | 512MB | ✗ 且 15 分钟无访问就休眠 |
| Fly.io | 部分 | ✅ | 256MB 档不够 | ✅ |
| Railway | $5 额度 | ✅ | 够 | ✅ |

这个应用光是加载 OR-Tools 跑一次最小求解就要 **93MB**，加上 pandas 和
FastAPI，常驻约 250–350MB —— **256MB 的免费档直接出局**。
HF Spaces 内存宽裕、不要卡，代价是重启清空数据，对 demo 可以接受。

## 步骤

### 1. 注册并建 Space

1. 注册 https://huggingface.co/join
2. 建 Space https://huggingface.co/new-space
   - Space name：随便起，比如 `edu-shift-scheduling`
   - License：随意
   - **Select the Space SDK → 选 `Docker` → Blank**
   - Visibility：Public 或 Private 都行

### 2. 推代码

两条路，选一条。

#### A. 用 GitHub Actions（推荐，不用在本地克隆）

1. 去 https://huggingface.co/settings/tokens 建一个 **Write** 权限的 Access Token
2. GitHub 仓库 → **Settings → Secrets and variables → Actions → New repository secret**
   - Name：`HF_TOKEN`
   - Secret：刚才那个 token
3. **Actions** 标签 → 左边选「部署到 Hugging Face Space」→ **Run workflow**
   - Space 填 `<你的HF用户名>/<space名>`

跑完在运行摘要里会列出后面要设的三个 Secret。

> Actions 需要仓库是公开的（私有仓库免费额度用完就拿不到 runner）。

#### B. 在自己电脑上跑

```bash
deploy/huggingface/push.sh <你的HF用户名>/<space名>
```

会让你输 HF 用户名和 **Access Token**（不是登录密码）。

两条路用的是同一个脚本：挑出运行需要的文件、补一份 htmx、推到 Space 的
git 仓库。测试、文档、`legacy/`、真实配置都不会上去。

### 3. 设 Secrets

Space 页面 → **Settings** → **Variables and secrets** → New secret：

| 名字 | 值 | 作用 |
|---|---|---|
| `SCHEDULING_PASSWORD` | 你要的口令 | 不设的话每次重启随机生成，只能去日志里翻 |
| `SCHEDULING_SECRET` | 任意随机串 | 不设的话重启就把所有人踢下线 |
| `SCHEDULING_SEED_DEMO` | `1` | 库空时自动灌示例数据 |

然后 **Settings → Factory rebuild**，等几分钟构建完。

### 4. 访问

`https://huggingface.co/spaces/<用户名>/<space名>`

打开是登录页，输口令进去。示例数据已经灌好，可以直接点「中心」「场地容量」
「区域相邻」看，也能建任务跑一次求解。

## 这个实例的性质

**别把它当成能放真实数据的地方。**

| | 说明 |
|---|---|
| 数据全是编的 | 中心名、地址、指导员都是虚构示例。真实门店信息与 106 位指导员姓名一路都没进过仓库，这里也不破例 |
| 重启会清空 | 免费档文件系统是临时的。Space 重建、休眠唤醒后，上传的文件和改过的配置都会没，系统自动重灌示例数据 |
| 只有门禁没有认证 | 全站一个共享口令、不分人、无审计、泄露只能换口令重启。见 [`部署.md`](部署.md#口令门禁) |
| 求解会被打断 | Space 休眠时正在跑的任务会丢。免费档不保证长时间运行 |

## 更新

改完代码重跑一次推送脚本即可：

```bash
deploy/huggingface/push.sh <用户名>/<space名>
```

脚本用的是 `push -f`，Space 的 git 历史会被覆盖 —— 那边本来就只是部署产物，
不是源码仓库。

## 排查

**构建失败**：Space 页面有 Build logs。多半是 `requirements.txt` 里某个包
在那边装不上。

**打开一直转圈**：Space 冷启动要几十秒（要装 OR-Tools 那 79MB）。
第一次慢是正常的。

**进去是空的**：`SCHEDULING_SEED_DEMO` 没设成 `1`，或者设完没 rebuild。

**忘了口令**：Space 的 Logs 里搜「口令：」。没设 `SCHEDULING_PASSWORD` 的话，
每次重启都是新的。
