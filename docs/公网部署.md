## ① 本机 + cloudflared 隧道（不用注册任何账号）

最适合「现在就想让同事点开看看」。

```bash
# 1. 起服务（在项目目录下）
docker compose up -d --build

# 2. 开隧道。cloudflared 的快速隧道不需要 Cloudflare 账号
#    macOS:  brew install cloudflared
#    其他:   https://github.com/cloudflare/cloudflared/releases
cloudflared tunnel --url http://localhost:8000
```

第二条命令会打印一个 `https://随机名字.trycloudflare.com` 的网址，
把它发给同事就行。

口令在 `docker compose logs scheduling | head -20` 里。

**注意**：
- 你的机器关了、或者 `cloudflared` 停了，链接就失效
- 每次重开隧道网址都会变
- 这条隧道把你本机的 8000 端口接到了公网上 —— 只有口令挡着，
  用完记得 Ctrl-C 停掉

要让数据不丢，把 compose 里的端口改回 `"8000:8000"` 之前先确认
只有隧道在访问，别直接绑 `0.0.0.0`。

## ② Render 免费档

有固定网址，适合放几天给人随时看。

### 步骤

1. 用 GitHub 账号登录 https://dashboard.render.com
2. **New → Blueprint** → 选这个仓库 → Render 会自动读根目录的 `render.yaml`
3. 它会问你填 `SCHEDULING_PASSWORD`（其余变量 `render.yaml` 里已经写好）
4. 点 Apply，等构建。**第一次要装 OR-Tools，慢，估计五到十分钟**

网址形如 `https://edu-shift-scheduling.onrender.com`。

### 免费档的两个坑

| | 说明 |
|---|---|
| **休眠** | 15 分钟没人访问就停。下次访问要等冷启动，这个应用因为 OR-Tools 体积大，估计半分钟往上。给人演示前先自己点一下唤醒 |
| **数据清空** | 持久磁盘要付费，免费档文件系统是临时的。重部署、休眠唤醒后上传的文件和改过的配置都会没 —— 所以 `render.yaml` 里开了 `SCHEDULING_SEED_DEMO=1`，醒来自动重灌示例数据 |

> 我没法从这个环境访问 Render 验证上面的额度细节，以你注册时页面上写的为准。
> 如果免费档也要卡了，就走方案 ①。

## 这个实例的性质

**别把它当成能放真实数据的地方。**

| | 说明 |
|---|---|
| 数据全是编的 | 中心名、地址、指导员都是虚构示例。真实门店信息与 106 位指导员姓名一路都没进过仓库，这里也不破例 |
| 重启会清空 | 免费档文件系统是临时的。Space 重建、休眠唤醒后，上传的文件和改过的配置都会没，系统自动重灌示例数据 |
| 只有门禁没有认证 | 全站一个共享口令、不分人、无审计、泄露只能换口令重启。见 [`部署.md`](部署.md#口令门禁) |
| 求解会被打断 | Space 休眠时正在跑的任务会丢。免费档不保证长时间运行 |

## 更新

改完代码重跑一次推送脚本即可：

```bash
deploy/huggingface/push.sh <用户名>/<space名>
```

脚本用的是 `push -f`，Space 的 git 历史会被覆盖 —— 那边本来就只是部署产物，
不是源码仓库。

## 排查

**构建失败**：Space 页面有 Build logs。多半是 `requirements.txt` 里某个包
在那边装不上。

**打开一直转圈**：Space 冷启动要几十秒（要装 OR-Tools 那 79MB）。
第一次慢是正常的。

**进去是空的**：`SCHEDULING_SEED_DEMO` 没设成 `1`，或者设完没 rebuild。

**忘了口令**：Space 的 Logs 里搜「口令：」。没设 `SCHEDULING_PASSWORD` 的话，
每次重启都是新的。
