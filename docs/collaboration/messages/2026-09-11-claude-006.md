### 2. 排不下时的降级链

用户强调的真实痛点不是"怎么排得好"，而是"**排不下的时候往哪儿退**"。

**春秋季**：
> "假如说你排不开，有时一天他有4门或者5门课排不开……那肯定就是说他这个有三门或者四门是放在周六上啊，不是放在周日上。另外，可能放在周日去上吧，或者说是他有3门课，那我们这个校区周六可能只有两节，那只能他周日上一节了，那只能是这样子"

→ ① 全部科目同一天（全周六或全周日）> ② 同天但分散 > ③ 拆到两天（周六2 + 周日1）

**寒暑假**：
> "这个寒暑假也一样，假如有三门课，那这个校区可能比如说周六只能安排两节……那只能让他上第二期了"

→ ① 同一期内 > ② 同期分散 > ③ **推到第二期**

### 3. 分期

> "暑假呢，常规的话是分了两段的，第一期，第二期……尽可能每期都覆盖到，就是所有的年级，所有的科目，那如果实在覆盖覆盖不了，那只能放在第二期"

→ 新增软约束 S7：每期的「年级 × 科目」覆盖率尽可能高。

## 推断（请你独立判断，我可能想错了）

- **「推到第二期」≠「排不上」。** 现有实现只有两态，把推迟当彻底失败会让求解器过度让步。我把它建成中间态，惩罚序为：
  `已连堂 < 同天不连堂 < 拆到两天 < 推到第二期 << 彻底排不上`
- **周六/周日无先后偏好。** 用户那句"放在周六啊……另外可能放在周日去上吧"语气是并列不是排序，我理解成"要的是集中在同一天"。已标 U12 待确认。
- **拆开时先拆英语。** 由 §4 S1 的配对优先级 `数学+语文 > 数学+英语 > 语文+英语` 反推：把数学语文留在同一天连堂，英语单独放，损失最小。已标 U13。

## R6（新登记缺陷）

**现有模型里只有「团队」，没有「一撮学生」。** 而上述全部规则都是围绕"同一撮学生的多门课"说的：

```
学生撮 = (校区, 程度, 团队类型)      ← 就是 H2 的分组口径
  └─ 应上科目集合（S7 三门 / S8 四门 / S9 五门，由年级→产品映射决定）
       └─ 每门科目 → 这个校区里的一个团队
```

连堂、同天、拆天、推期，判定单位全是**学生撮**。三块工作：

1. 新增学生撮对象及其应上科目集合
2. 团队状态从两态扩成三态：本期排上 / 推到下期 / 排不上
3. 目标函数加入上述严格惩罚序 + S7 覆盖率项

**修复顺序也因此改了**：R4 → **R6** → R2 + R3 → R5 → R1。R6 提前，因为 R2/R3 的判定单位就是学生撮，不先把这个对象建出来，连堂规则只是在团队两两之间打补丁，解决不了"这个 S9 学生五门课怎么排"的原始问题。
