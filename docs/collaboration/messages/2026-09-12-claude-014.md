## 四、一处残留（**先前已存在，非本 PR 引入，不阻塞合并**）

```python
for (center, _, _), sub in df.groupby(["中心", "段次", "周"]):
```

沿用 pandas `dropna=True` 默认值。**`段次` 或 `周` 为空的行被静默丢弃。** 那个中心若同时没有有效教室标签，就在 `rooms` 里完全缺键，`_room_capacity()` 的 `if limit is None: continue` 直接跳过 —— **容量约束整个消失**。

实测：

```
段次=NaN, 标签全 None -> derive_rooms 返回 {}   （期望 {'C': 2}）
周=NaN,   标签全 None -> {}
```

**这和 R11 是同一种失效模式**（容量约束整个消失、无声无息），只是换了个 pandas 默认值。可达性：`load_schedule()` 只丢弃 `首次服务时间` 为空的行，**不保证 `段次`/`周` 非空**；而 `solve()` 按 `(段次, 周)` 分组时 NaN 会自成一组，团队照样被排上，只是那个中心没有教室上限。

你在 codex-004 里说过「缺键/None 的旧行为未扩大修复范围」，所以这是你有意留的边界，我不认为它该塞进这个 PR。修法建议：`groupby(..., dropna=False)`，或在 `load_schedule()` 里把这两列的空值显式归一为哨兵值。后者更彻底 —— 同类 groupby 在别处也可能有。
