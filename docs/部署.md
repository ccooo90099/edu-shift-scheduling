# 内网部署

> ⚠️ **这份 Dockerfile 与 compose 文件从未被真正构建运行过。**
> 开发环境里没有 Docker daemon，我只验证了镜像内要跑的那两条命令
> （`uvicorn` 启动、`HEALTHCHECK` 探活）在容器外成立。
> 第一次部署时请按下面的「首次部署检查」逐项确认。

## 前置：放一份 htmx.min.js

仓库里**没有**这个文件，必须手动放：

```bash
curl -o src/scheduling/interfaces/web/static/htmx.min.js \
  https://cdnjs.cloudflare.com/ajax/libs/htmx/1.9.12/htmx.min.js
```

**为什么不从 CDN 加载**：内网很可能连不上外网。从 CDN 取会让页面**静默降级** ——
HTML 照常渲染，但所有 `hx-*` 失效，用户看到的是一个永远停在「求解中」的页面，
而且不报任何错。缺文件时页面顶部会挂一条提示，不会让人对着假进度干等。

## 口令门禁

访问需要一个口令。不设环境变量的话，**每次启动随机生成一个**，打在启动日志里：

```
========================================================
  排班系统已启动，访问需要口令

    口令：dkgFLpVvadWE

  ⚠ 这是本次启动随机生成的，**重启就会换一个**。
    要固定下来，用环境变量：SCHEDULING_PASSWORD=你的口令
========================================================
```

```bash
docker compose logs scheduling | head -20      # 看口令
```

固定下来：在 compose 的 `environment` 里设 `SCHEDULING_PASSWORD`。
再设一个 `SCHEDULING_SECRET`（任意随机串），重启就不会把人都踢下线。

### ⚠️ 这是门禁，不是认证

差别要说清楚，别当成安全模块用：

| | 门禁（现在有的） | 认证（现在没有） |
|---|---|---|
| 粒度 | 全站**一个共享口令** | 每人一个账号 |
| 审计 | 查不出谁改了什么 | 有操作人 |
| 吊销 | 只能换口令 + 重启，所有人一起换 | 停单个账号 |
| 挡谁 | 误闯的路人 | 有心的攻击者 |

**它不会让公网部署变得安全。** 里面的中心地址、指导员配置照样只隔着一个
共享口令。真实数据不要放进公网实例 —— demo 用假数据。

放行的路径（不需要口令）：`/login`、`/static/*`、`/healthz`。
**探活必须用 `/healthz`**，拿 `/api/readiness` 当探活的话容器会一直被判成不健康。

## 起服务

```bash
mkdir -p data config
cp config/rules.example.yaml config/rules.yaml    # 按实际情况改
docker compose up -d --build
```

打开 `http://<内网地址>:8000`。

## 目录与卷

| 宿主机 | 容器内 | 放什么 |
|---|---|---|
| `./data` | `/app/data` | 上传的 xlsx、产物、SQLite 库 |
| `./config` | `/app/config`（只读） | `rules.yaml`、`centers.csv`、`travel.csv` |

**这三个 config 文件含真实门店坐标与规则，不入库**（`.gitignore` 已覆盖）。
只读挂载是为了避免容器把它们改坏。

## 端口只绑内网

compose 里写的是：

```yaml
ports:
  - "127.0.0.1:8000:8000"
```

**这个服务不做认证** —— 用户定案：内网部署，谁能访问谁能用。所以：

- 改成 `"8000:8000"` 会暴露到宿主机所有网卡上
- 要让同事访问，把 `127.0.0.1` 换成**内网网卡地址**（如 `192.168.1.10:8000:8000`），
  或者在前面放一层只监听内网的反向代理
- **不要**让它出内网

## 首次部署检查

按顺序做完，每一项都会在页面顶部的告警条里体现：

| # | 事 | 不做的后果 |
|---|---|---|
| 1 | 导入中心清单，跑坐标自动反查，剩下的手动补 | 跨中心的路上时间只能按同校区/同区域/跨区域三档粗判，「赶不赶得及」基本失效 —— **而且不报错** |
| 2 | 导入指导员名单，配可教产品、可去中心、不可用时段 | 资质与可用性约束落空，可能把人排到他去不了的中心 |
| 3 | 填学年日历（寒假/暑假/春季/秋季的起止日期） | 排班展不开成真实日期，跨批次的指导员撞车查不出来 |

坐标准备（各跑一次，之后排班完全离线、不需要网络也不需要 key）：

```bash
docker compose exec scheduling python tools/geocode_centers.py   # 默认 OSM，免 key
docker compose exec scheduling python tools/travel_matrix.py
```

反查不到的中心在网页「中心」页手动补：选**地图来源**（高德/腾讯/百度/天地图/OSM），
粘经纬度即可 —— 不用管坐标系，系统按来源自己折算。

> 三家坐标系在深圳两两相差 300–700 米。百度用的是 BD-09，**不是**高德腾讯那种
> GCJ-02，当成同一种处理会再差几百米。所以来源认不出来时系统直接报错，不猜。

## 备份

要备份的只有两处：

```bash
tar czf backup-$(date +%F).tar.gz data/ config/
```

`data/scheduling.db` 是 SQLite 单文件，停服务后直接拷就行。

## 升级

```bash
git pull && docker compose up -d --build
```

数据在卷里，不受影响。**升级前先备份** —— 目前没有数据库迁移脚本，
表结构变了要手工处理。

## 规模与并发

单 worker。内网并发个位数，求解本身在应用内的线程池里跑（默认 2 个并发任务）。

**不要多开 uvicorn worker** —— 任务状态会分散在各进程的内存里，
轮询进度时可能问到没跑这个任务的那个进程。要横向扩再说，那需要先把
任务队列挪出进程。

## 已知限制

- **求解可能很久不收敛。** 大候选池下曾出现 140 秒仍停在 FEASIBLE。
  界面会如实显示求解状态和与下界的差距，别把 FEASIBLE 当成「排好了」。
- **没有认证。** 见上面「端口只绑内网」。
- **没有数据库迁移。** 表结构变更需手工处理。
- **教室数可能是估计值。** 从历史并发峰值推出来的会在界面上标「估计」，
  不等于经过核验的真实场地清单。
