## 0. 业务背景

深圳某**教培**机构（**不是托管/晚托**）的分校排课。学生按报名科目来上课，课间不留校，午休由家长接走。

现状是人在 Excel 里把两百多个团队手工拖进「中心 × 时段」的格子里。本系统要把这件事反过来做：**给定要开的课 + 可用的指导员 + 规则，自动排出这张表**，并给出看板视图和冲突报告。

```
输入：待排团队清单 + 指导员池 + 场地 + 规则参数 + 场景（寒暑假/春秋季）
  ↓  CP-SAT 求解
输出：① 排班明细（列结构与现有导出一致，可回灌体检）
      ② 中心 × 时段 看板
      ③ 指导员个人课表 + 工作量统计
      ④ 冲突 / 未排上 报告（含牺牲了哪些软约束）
```

## 1. 领域概念

### 1.1 产品 ↔ 科目 ↔ 年级 【用户定案】

| 产品名 | 实际科目 | 开设年级 |
|---|---|---|
| 编程理论 | 数学 | S7 起 |
| 双语文化 | 英语 | S7 起 |
| 文学美育 | 语文 | S7 起 |
| 躬行实践 | 物理 | **S8 起** |
| 溯源 | 化学 | **S9 起** |

即：初一语数英三科；初二加物理；初三加化学。产品名是内部叫法，排课逻辑上就是科目。

> **年级 → 可开产品是一条硬约束**：S7 不应出现躬行实践/溯源。
> 【已验证】原表中 S7 确实没有这两个产品的行。

### 1.2 程度（年级） 【用户定案 + 已验证】

`程度` = 年级。当前项目取值 **S7 / S8 / S9**（初一/初二/初三）。

一个学生只属于一个程度，且跨产品不变 —— 所以**程度是"同一撮学生"的判定字段**，这是 H2 冲突口径的基础。

配置项：`冲突口径.分组字段`，默认 `[校区, 程度]`。

### 1.3 团队类型（层级） 【用户定案】

| 代码 | 全称 | 用户确认 |
|---|---|---|
| LI | 励学 | "利" = LI 励学 ✅ |
| LE | 乐学 | "绿" = LE 乐学 ✅ |
| BO | 博学 | KT/KD 指 KP-BO ✅ |
| CX | 创新 | KT/KD 指 KP-CX ✅ |
| ZY | 卓越 | — |

这是**能力分层**。用户原话："程度必须匹配，利和绿，乐和乐，KT 跟 KD"——即**排在一起的课，层级要一致**，不能把励学班和乐学班的学生混着连堂。

### 1.4 中心 vs 校区 【已验证 · 关键】

30 个**中心**实际落在 20 个**校区**上：`百花科学` 和 `百花文学` 是同一个校区的两栋楼。

- **校区**是学生感知的地点 —— 冲突判定、"同地点"判定都按校区
- **中心**是排课和场地的单位 —— 教室归中心
- 派生规则：中心名去掉 `科学` / `文学` 后缀 = 校区名

【已验证】文学中心只上文学美育（26/26 行）；科学中心和综合中心什么都上。所以「产品 → 可用中心」本身就是一条硬约束。

### 1.5 期位 —— 两个场景共用的同一个维度 【用户定案 · 关键简化】

暑假**常规班分两期**：第一期、第二期。目标是**每期都尽可能覆盖所有年级 × 所有科目**，覆盖不了的才放到第二期。

**而春秋季的周六 / 周日，就是这两期平移过去的结果**。用户原话：

> "假如说是暑假有两期的话，那么把第一期的课程通常就会平移到周六去上课……第二期的课程通常会平移到周日上课。"

所以两个场景不需要两套模型，只有**一个抽象维度**，在不同场景下换个名字：

| 抽象维度 | 寒暑假 | 春秋季 |
|---|---|---|
| **期位 A** | 第一期 | **周六** |
| **期位 B** | 第二期 | **周日** |

这带来三个直接结论：

1. **「拆到两天」和「推到第二期」是同一个降级动作** —— 都是"把排不下的科目挪到另一个期位"。§4.5 的两张降级表其实是一张。
2. **周六 / 周日 不是随便挑的**（修正了我先前的推断 U12）—— 一撮学生在假期里是第一期，春秋季就接着上周六。**期位是跟着学生走的，有延续性。**
3. 模型里不需要「期」和「星期」两个维度。给团队一个**期位变量**就够了，渲染成"第一期"还是"周六"是输出层的事。

> **【未知 U9】** 原表的 `段次1–4` 与期位的对应关系。是"常规两期 + 促销两期"，还是别的切法？
> **【未知 U14】** 一个**新生**（没有上过假期班、没有历史期位）怎么定期位？是自由分配，还是有别的规则？
> **【未知 U15】** 学生能不能**中途换期位**（本来周六，下学期改周日）？如果不能，这是硬约束；如果能，是软约束。

### 1.6 团队 = 一个班

一行明细 = 一个团队 = `(中心, 程度, 产品, 团队类型, 班序)`，有固定人数（【已验证】均值 15.9，容量 24），要被分配到一个 `(日期/星期, 时段, 主指导员, 指导室)`。

## 2. 两个场景 【用户定案】

**两个场景的排课逻辑是同一套** —— 用户原话："寒暑假跟周末，平时周末其实一样的"。
区别只在两处：**时段表**，以及**「一个批次由哪些天组成」**。真正的业务难点在两边是同一个：排不下的时候往哪儿退（见 §4.5）。

### 2.1 寒暑假场景

- 一个批次**连上 7–8 天**，中间不休；若拉到 15 天，中间会休息一次
- **不区分星期几** —— 不存在"只有周六上"这回事，每天都是上课日
- 全天开课，用完整时段表

【已验证】原表四个段次全部符合该结构：

| 段次 | 推算首次上课日 | 该日星期 | `周` 字段 | 末次 | 次数 |
|---|---|---|---|---|---|
| 段次3 | 2024-08-02 | 星期五 | 星期五 | 2024-08-11 | 9 |
| 段次4 | 2024-08-16 | 星期五 | 星期五 | 2024-08-25 | 9 |
| 段次2 | 2024-07-19 | 星期五 | 星期五 | 2024-07-28 | 9 |
| 段次1 | 2024-07-06 | 星期六 | 星期六 | 2024-07-16 | 9 |

> **`周` 字段是「首次上课那天是星期几」，不是「每周星期几上课」。**
> 这一点此前被双方误读，导致把 `(段次, 周)` 当成互不相干的子问题（见 §7 R1）。

### 2.2 春秋季场景

- **周末两天为主**（周六、周日都开课）
- 偶尔有**周五晚上**的课，且**周五只开 18:30-20:30 这一档**
- 指导员作息：**周一、周二休息；周三/周四/周五教研**

### 2.3 时段表 【用户定案】

| 时段 | 寒暑假 | 春秋季 周六/周日 | 春秋季 周五 |
|---|---|---|---|
| 08:10-10:10 | ✅ | ✅ | ✗ |
| 10:30-12:30 | ✅ | ✅ | ✗ |
| 14:00-16:00 | ✅ | ✅ | ✗ |
| 16:20-18:20 | ✅ | ✅ | ✗ |
| 18:30-20:30 | ✅ | ✅ | ✅ **仅此一档** |

> 原表里还出现过 `13:30-15:30`，与 `14:00-16:00` 重叠。**【未知】**：这是历史遗留还是仍在用的并行档？两者重叠会让 H2 判定复杂化，需要用户定案。目前实现按"两者都存在且按时间重叠判冲突"处理。

### 2.4 时段间隙结构 【已验证 + 用户定案】

```
08:10-10:10 → 10:30-12:30    空 20 分钟   ← 课间
10:30-12:30 → 14:00-16:00    空 90 分钟   ← 午休
14:00-16:00 → 16:20-18:20    空 20 分钟   ← 课间
16:20-18:20 → 18:30-20:30    空 10 分钟   ← 课间
```

用户确认："**午休本身是有 120min 间隔，但上午和下午之间课程之间的间隔就是按照目前数据里面推算出最小间隔即可**"。

系统自动从时段表推导"课间 vs 休息"的分界：找相邻等待时间序列 `[10, 20, 50, 60, 90]` 里最大的比值跳变（20→50 是 2.5 倍），得出**上限 = 20 分钟**。10/20 分钟算课间，50 分钟以上算休息。

## 3. 硬约束（违反 = 排班不可用）

| # | 约束 | 来源 | 原表执行情况 |
|---|---|---|---|
| **H1** | 一个指导员同一时段只能带一个团队 | 常识 | 【已验证】批次内 0 违反 —— 但**跨批次有 21 处**，见 §7 R1 |
| ~~**H2**~~ | ~~同时段 + 同校区 + 同程度 + 不同产品 不能同时开课~~ | **已降级为软约束 S8**，见 §3.1 和 §4.6 | 原表 409 组里 164 组"违反"—— **那不是违反，是有意为之** |
| **H3** | 同时段同中心并发团队数 ≤ 教室数 | 场地上限 | 【已验证】有教室数据的行 0 违反 |
| **H4** | 只能把指导员排到他能教的产品上 | 资质 | 【已验证】106 人中 103 人只教 1 个产品；唯一跨产品组合是「溯源+躬行实践」（3 人） |
| **H5** | 年级 → 可开产品（S7 无物理/化学） | 【用户定案】§1.1 | 【已验证】原表符合 |
| **H6** | 指导员/中心/时段可用性黑名单 | 请假、限定中心 | **【未知】**：需要新增输入，当前无数据 |

### 3.1 H2 的降级 —— 我此前把它定错了 【重大修正】

**先前的写法（错的）**：H2 是硬约束，是本系统最大的价值点，原表 40% 违反是需要修的问题。

**用户澄清（对的）**：

> "我们这个教室是没办法……很难兼顾到把时间所有的都去平铺开来、不冲突的，做不到。那可能就是必须要冲突啊，必须要同一个时间段上两个课或者是三个课。那些学生他可能并不是在读三科，可能就读了两科啊，就只有数学物理，或者是只有数学语文这种，那么他 10 点钟的这两科也不会有什么冲突。"

用户举的例子：

```
08:10-10:10  数学
10:30-12:30  语文  ┐ 同一时段两个产品
10:30-12:30  物理  ┘ —— 这是允许的
```

**为什么原表那 40% 不是错误**：

1. **教室和时段容量根本不够**把所有产品平铺开。硬要不冲突，就是无解。
2. **不是所有学生都读全科** —— 只读「数学+物理」的学生，10:30 那格同时开语文和物理并不影响他。
3. 还有一部分学生家长时间凑不齐，**主动只选一科**（用户原话："他可能会去选其中的一科，会去相应的一些取舍"）。

**真正的约束是什么**：不是"同程度的不同产品不能同时段"，而是——

> **同一个学生实际报读的那几科之间不能撞时段。**

这是一个**窄得多**的约束。它的代价正比于**同时报了这两科的学生人数**，而不是"存在两个不同产品并发"这个事实本身。

**这个错误的实际后果**：我先前的求解器把一个软约束当硬约束建模，问题被**过度约束**了 —— 这很可能就是它排不开、转场次数离谱（31 次/天）、140 秒不收敛的根因之一。已登记为缺陷 **R7**。

> **实现注意仍然有效**【已验证】：时段之间存在时间重叠（13:30-15:30 × 14:00-16:00），并发判定必须对**所有不相等的产品对**双向做，只做 `p1 < p2` 单向会漏掉 8 处。降级成软约束后这条同样适用。

## 4. 软约束（可加权取舍）

### S1 连堂 —— 学生视角 【用户定案】

用户原话（学生视角）：一个学生报语数英三科，希望三节课能挨在一起上完，而不是"早上 8 点上一个，下午两点到 4 点上一个，4 点到 6 点再上一个"。

**规则细节**：

1. **配对优先级由实际报读组合驱动，不是固定顺序** 【用户定案 · 修正】
   常见搭配是 `数学+语文`、`数学+英语`、`语文+英语`，**但也有很多是 `数学+物理`**。用户原话：

   > "我们排的时候肯定是先排一种可能嘛，对吧？然后呢，如果说他后续比如说上了数学物理的学生比较多，那可能会把数学物理放在一起去排，就是放在同一个上午或者同一个下午这种时间连续的。"

   → 这是一个**两阶段**的过程：先按默认顺序排一版，再根据**实际报读组合的人数分布**调整，把人多的组合优先安排连堂。
   → 所以配对权重应当是**输入数据**（各科目组合的学生人数），而不是写死在配置里的顺序。缺这份数据时才退回默认顺序 `数学+语文 > 数学+英语 > 语文+英语`。
   → **【未知 U16】** 各科目组合的学生人数，这份数据拿得到吗？拿不到的话，能不能用"上一期的排班结果 + 各班人数"近似？
2. **层级必须一致** —— 连堂的两节课必须同校区、同程度、同团队类型（§1.3）
3. **跨午休算连堂** 【用户定案 · 修正了旧文档】
   用户原话："跨午休到底也算连，尽可能一个半天，比如一个上午或者下午，实在不行只能分散，这也是次优选项了"
   → 三档偏好，从好到差：
   - **① 同半天连排**（8:10→10:30，或 14:00→16:20→18:30）—— 最优
   - **② 跨午休连排**（10:30→14:00）—— 可接受，次优
   - **③ 分散**（中间隔了别的时段）—— 次优选项，能排上就行
4. **只看当天** 【用户定案】用户原话："当天连在一起即可"
   → 连堂判定**不跨日**。日期/星期由场景和批次决定，不是决策变量。

> ⚠️ **当前实现与本节不符**，见 §7 R2：现有代码把 `最大间隙_分钟: 自动` 推出的 20 分钟当硬门槛，等于把"跨午休"判为不连堂——与用户定案相反。

【已验证】原表现状：真正同半天挨着的只有 **38%**（51/135）；另有 22% 是跨午休的 10:30→14:00。按新口径，实际达标率是 60%。

### S2/S3 转场 —— 指导员视角 【用户定案】

用户原话（老师视角）的反面教材："8 点在宝安带，10 点又到南山去，下午两点又跑到宝安去，4 点又跑到南山，这样他就太折腾。"

| # | 约束 | 说明 |
|---|---|---|
| S2 | 指导员当天尽量固定在一个中心 | 【已验证】原表 72% 的老师当天只在 1 个中心 |
| S3 | 必须跨中心时，越近越好，且要留够路上时间 | 优先级：同校区 > 同区域 > 跨区域 |

**转场计数口径** 【用户定案 + 已与 Codex 对齐】：按**相邻课之间实际发生的中心变更**计数。`A→B→A` 记 **2 次**，不是"去过 2 个中心 = 1 次额外"。里程按每次事件累加。

> ⚠️ **当前实现口径不一致**，见 §7 R4：求解目标算的是"额外活动中心数"（distinct − 1），体检算的是"实际转场事件"。同一份排班一个报 19 一个报 25。

**赶路时间判定**：`可用间隔 ≥ 通行时间 + 安全余量`。数据来源按可信度排队：

| 顺序 | 来源 | 怎么来的 |
|---|---|---|
| ① | `config/travel.csv` | 真实驾车时间/里程，地图 API 跑一次 |
| ② | 经纬度直线估算 | 直线 km × 折算系数 ÷ 车速 + 固定开销 |
| ③ | 同校区 / 同区域 / 跨区域 档位 | 连坐标都没有时的兜底，报告里明确标出 |

> **兜底必须保守**：区域未知的一律按"跨区域"算。让两个 `None` 相等而判成"同区域"，会因为缺数据反而**放宽**约束。

【已验证】原表有 24 次转场只有 10–20 分钟间隔（例：10 分钟内从罗湖翠竹赶到福田东海城市广场），在地图上不可能完成。

## 4.5 排不下时的降级链 【用户定案】

§4 S1 讲的是"能排下的时候怎么排得好"。本节讲**排不下的时候往哪儿退** —— 这是用户强调的实际痛点，两个场景通用。

### 4.5.1 为什么会排不下

一撮学生（= 同校区 + 同程度 + 同层级，即 §3 H2 的分组口径）要上的科目数是固定的：

| 程度 | 科目数 | 科目 |
|---|---|---|
| S7 | 3 | 语文、数学、英语 |
| S8 | 4 | + 物理 |
| S9 | 5 | + 化学 |

而一个校区一天能给这撮学生开的节数是有限的 —— 受教室数、可用师资、时段数共同约束。用户原话："**我们这个校区周六可能只有两节**"。3 门课塞不进 2 个位置，就必须降级。

> **【未知 U11】** "一个校区一天最多给一撮学生开几节"这个上限，是从教室数和师资**算出来**的，还是有人另外**规定**的一个数？如果是后者，需要作为输入项。

### 4.5.2 降级顺序（从好到差）

因为期位是两个场景共用的同一个维度（§1.5），降级链**只有一张表**：

| 档 | 安排 | 寒暑假读作 | 春秋季读作 | 依据 |
|---|---|---|---|---|
| ① | 全部科目在**本期位内**，且同半天连堂 | 都在第一期，同半天 | 都在周六，同半天 | 最优 |
| ② | 都在本期位内，但跨午休或分散 | 同期不同天/不同半天 | 同一天但有空档 | 见 §4 S1 的第②③档 |
| ③ | **挪一部分到另一个期位** | 推到第二期 | 周六 2 节 + 周日 1 节 | 用户原话见下 |
| ④ | 彻底排不上 | — | — | 最差 |

用户对第③档的两处原话，说的是同一件事：

> （春秋季）"那我们这个校区周六可能只有两节，那只能他周日上一节了，那只能是这样子"
> （寒暑假）"那这个阶段只能安排两节，那只能让他上第二期了"

### 4.5.3 期位不是自由选的 【用户定案 · 修正了先前的推断】

先前我推断"周六周日无所谓，集中在同一天即可"（旧 U12）。**这个推断是错的**，已按用户补充更正：

> "第一期的课程通常就会平移到周六去上课……第二期的课程通常会平移到周日上课"

**期位跟着学生走，有跨季延续性**：假期上第一期的那撮学生，春秋季接着上周六。所以春秋季的期位在有历史数据时是**继承来的输入**，不是决策变量。

只有没有历史期位的新生才需要分配（见 U14）。

### 4.5.4 拆开时先拆哪一门 【用户定案】

> "语数理化放在了同一天，那剩下的语文英语可能就放在另外一天。"

→ **把人数最多的那几个组合留在同一天连堂，剩下的拆出去**。跟 §4 S1 第 1 条一样，这由实际报读组合的人数分布决定，不是固定顺序。

先前我推断"英语最容易被拆出去"（旧 U13），那只在默认顺序下成立；一旦某个校区数学+物理的学生特别多，被拆出去的就可能是别的科目。

### 4.5.5 对目标函数的影响

降级链要在目标函数里体现成一条**严格递增的惩罚序列**：

```
已连堂  <  本期位内不连堂  <  挪到另一个期位  <<  彻底排不上
惩罚 0                                              惩罚最大
```

注意 **「挪到另一个期位」不等于「排不上」**。现有实现只有"排上/没排上"两种状态，把挪期位当成失败会让求解器过度让步。这是新登记的缺陷 **R6**。

同时新增一条软约束：

| # | 约束 | 说明 |
|---|---|---|
| **S7** | 每期的「年级 × 科目」覆盖率尽可能高 | 用户定案：尽可能每期都覆盖到所有年级所有科目 |

### 4.5.6 这需要一个新的建模对象

现有模型里只有**团队**，没有**「一撮学生」**。而 §4.5 全部规则都是围绕"同一撮学生的多门课"说的：

```
学生撮 = (校区, 程度, 团队类型)
  └─ 应上科目集合（由 §1.1 的年级 → 产品映射决定：S7 三门 / S8 四门 / S9 五门）
       └─ 每门科目对应这个校区里的一个团队
```

连堂、同天、拆天、推期，判定单位全是**学生撮**，不是单个团队。这是 R6 的主要工作量。

## 4.6 新增软约束（本轮用户补充）

| # | 约束 | 依据 |
|---|---|---|
| **S8** | **同校区同程度的不同产品，尽量不要同时段并发** —— 惩罚正比于同时报了这两科的学生人数 | §3.1 —— 由原 H2 降级而来。不是不能撞，是撞了要扣分，扣多少看伤到多少人 |
| **S9** | **周六（期位 A）优先** | 【用户定案】"周六其实更好排" |
| **S10** | **同一校区同一程度，周六和周日都要有班** | 【用户定案】新生按程度进班，"那有可能是排在周六，有可能排在周日，那就看家长的时间或学生的时间能不能错得开"；老生也能中途换班。两天都有班，家长才有得选 |

## 4.7 新生进班与中途换班 【用户定案】

**新生**（没上过假期班、春秋季直接进）：

> "他是会直接进，比如说周六有班那就进周六班，周日有班就进周日班。一是根据他的程度来进班，比如说他稍微好一点，那可能他就进到程度好一点的班……那有可能是排在周六，有可能排在周日，那就看家长的时间或学生的时间能不能错得开了。"

→ 两步：**先按程度和层级定进哪个班型**，**再看家长时间定周六还是周日**。
→ 对排班系统的要求：**不是**由系统给新生分配期位（那是招生环节的事），**而是**保证每个校区每个程度在两个期位上都有班可进（= S10）。

**中途换班**：

> "中途能换的，比如说他周六早上的时间不合适，那可能他换到别的班……这个校区周六日两天有别的班，他也可以有合适的，他也可以选。"

→ **U15 有答案了：能换。** 所以期位延续性是**软约束**不是硬约束 —— 我先前的实现判断是对的。
→ 换班的前提同样是 S10：同校区两天都得有班。

## 5. 目标函数

硬约束进模型当约束，软约束进目标函数加权求和，权重全部可配：

```
minimize  w1 × 彻底排不上的团队数            （压倒性权重）
        + w2 × 学生撮被拆到两个期位的撮数    （§4.5 —— 比排不上轻得多）
        + w3 × 期位与历史不符的团队数        （§4.5.3 延续性）
        + w4 × 连堂未达标的对数（按 §4 S1 三档分别计分）
        + w5 × 各期「年级 × 科目」未覆盖的组合数   （§4.5 S7）
        + w6 × 指导员当日转场次数
        + w7 × 转场里程分
        + w8 × 指导员课表空档段数
        + w9 × 工作量峰值
        + w11 × 同校区同程度产品并发的受影响学生数   （§4.6 S8 —— 原 H2 降级）
        + w12 × 期位 B（周日）上的团队数              （§4.6 S9 —— 周六优先）
        + w13 × 同校区同程度只有单边期位有班的组合数  （§4.6 S10）
        + w10 × 与原排班不同的格子数         （仅 repair 模式）
```

权重必须满足 §4.5.5 的严格序：`w1 >> w2 > w3 > w4`。w2–w5 和 S7 是本次新增的，代码里还不存在（缺陷 R6）。

> **配置陷阱**【已验证】：`config/rules.yaml` 里的 `权重` 块会**整块覆盖**代码默认值。历史上曾出现连续三轮调权重（20→150→800）完全不生效，因为配置文件里还留着旧值。**必须做**：加载后打印实际生效的权重表。

副产品：有了这个打分函数，就能**给现有手工排班打分**，量化"工具比手排好了多少"。

## 6. 输入 / 输出

### 6.1 输入

**① 待排团队清单** —— 要开哪些课
```
期位 | 中心 | 程度 | 产品 | 团队类型 | 平行班数量 | 是否促销 | 本团队服务次数
```

**①b 各科目组合的学生人数**（**新增 · 最关键**，见 U16）
```
校区 | 程度 | 团队类型 | 科目组合（如 数学+物理） | 人数
```
S8 的惩罚力度和 S1 的配对优先级都靠它。拿不到就退回默认顺序，但排出来的结果会偏离实际报读结构。

**② 指导员池**
```
主指导员 | 可教产品 | 可去的中心（或区域） | 不可用的星期/时段 | 单日最多几节
```
候选池口径三选一：`不限`（31 候选）/ `就近`（9）/ `历史`（3）。默认 `就近`。

**③ 场地**
```
中心 | 教室数 | 各教室座位数
```

**④ 规则参数**（yaml，改规则不动代码）
```
场景：寒暑假 | 春秋季
时段表、冲突口径分组字段、连堂规则与优先级、
地理判定方式（时间/距离）、单人单日上限、各项权重
```

**⑤ 批次起始日期**（可选） —— 【新增】用于跨批次冲突检查，见 §7 R1

### 6.2 输出

1. **排班明细表** —— 列结构与现有导出一致，可直接回灌体检做 diff
2. **看板透视** —— 行 = 区域/校区，列 = 段次 × 时段，格子里 `程度/类型/产品简称/主指导员/人数`
3. **指导员课表 + 工作量统计**
4. **冲突 & 未排报告** —— 哪些团队没排上、为什么（缺老师？缺教室？时段冲突？），牺牲了哪些软约束

### 6.3 两种模式

- `rebuild` —— 从零重排
- `repair` —— 在现有排班上做最小改动（学期中途只能修不能推翻），额外惩罚"与原排班不同"
